# 사전 등록 Stage 1: 독립 확증 전에 고정하는 가설, 판정 규칙, 데이터 절차

이 문서는 새 이미지 풀을 만들기 전에 커밋한다. 커밋 시각이 등록 시점이다.
여기에는 결과 수치를 적지 않는다. 지금까지의 탐색 결과는 비공개 파일에 있고, 그 파일의 SHA-256을 9절에 적는다.
방법의 파라미터(손상 한도, 판정 기준, 구간 수준)는 이 문서와 코드에 공개로 적는다.

등록은 두 단계다.
- Stage 1 (이 문서): 새 풀을 만들기 전. 가설, 판정 규칙, 관문, 데이터 구축 절차, 통계 방법
- Stage 2: 확증 풀에서 추론하기 전. 새 프롬프트(One-pass D, 반전 질문), 신규 VLM의 체크포인트와 revision SHA,
  추가 변형(NNP, NPN)과 이미지 수 실험의 케이스 구성, 확증 분석에 쓸 코드의 커밋, 각 풀 파일의 SHA-256
- 개입 연구(로드맵 19~25)의 세부 규칙은 그 단계를 시작하기 전에 따로 등록한다.

## 1. 범위와 현재 상태

- 탐색 데이터: 기존 이미지 311장, 20개 클래스, 케이스 2,400개 (`data/cases/cases.jsonl`).
  지금까지의 모든 분석(기본 추론, A/B/C, hidden state, probe, 클래스 내부 민감도, P→P 대조, Evidence Link,
  Fixed Logit Bias, 자리별 기울기와 가중치(7-A), 클래스별 손상 한도(8-A))은 이 데이터를 보며 설계했으므로 탐색적이다.
- 탐색 결과 중 저장된 예측을 읽는 분석(클래스 내부 민감도, P→P 대조, Evidence Link, Fixed Logit Bias, 8-A, 7-A)은
  등록 전에 커밋 d97d2cd의 코드로 다시 실행해, 저장된 수치가 그대로 재현됨을 확인했다. 그 기록은 비공개다.
- 탐색 데이터는 확증에 다시 쓰지 않는다.
- 확증의 대상은 새로 뽑는 확증 풀이다. 판정은 아래 규칙으로만 내린다.

## 2. 데이터 계획

### 2.1 풀 세 개

| 풀 | 쓰임 | 허용되는 작업 |
|---|---|---|
| 개발 (dev) | 프롬프트 설계, 개입 방법 개발 | 층, head, 강도, 선택 규칙을 고른다. 성능 주장에 쓰지 않는다 |
| 확증 (confirm) | 3절의 확증 가설 | 등록된 분석만 판정에 쓴다. 그 밖의 분석은 탐색으로 표시한다 |
| 봉인 평가 (eval) | 최종 방법의 1회 평가 (G5) | 방법을 개발 풀에서 고정한 뒤 한 번만 연다. 결과를 보고 방법을 고치지 않는다 |

### 2.2 구축 절차

- 원천: COCO val2017 이미지 5,000장과 COCO-ReM 주석 `instances_valrem.json` (기존과 같음).
- 클래스: 기존 `data/cases/pools.json`의 20개 category id를 그대로 쓴다. 다시 고르지 않는다.
- 후보 정의 (기존 `scripts/build_pools.py`와 같음)
  - P: crowd가 아닌 해당 클래스 bbox 중 하나 이상이 이미지 면적의 5% 이상
  - N: 해당 클래스 주석이 크기와 상관없이 하나도 없음
- 제외: 기존 311장 전부, 그리고 먼저 만든 새 풀의 이미지 전부를 역할(P, N)과 클래스에 상관없이 후보에서 뺀다.
- 구축 순서: dev → confirm → eval. 세 풀을 모두 만든 뒤에 어떤 추론도 시작한다.
- 크기: 풀마다, 클래스마다 P 8장, N 8장.
- 뽑기: 후보를 image id 오름차순으로 정렬한 뒤 `random.Random(f"42:{풀 이름}:{category id}:positive_candidates").sample(후보, 8)`,
  N은 `negative_candidates`로 같은 방식. 풀 이름은 `dev`, `confirm`, `eval`이다.
- 한 풀 안에서는 기존 절차처럼 클래스마다 따로 뽑는다. 그래서 한 이미지가 한 풀 안에서 여러 클래스에 쓰일 수 있고,
  그 수를 보고한다. 풀 사이의 중복은 허용하지 않는다.
- group, pair, 케이스: 기존 `scripts/build_pairs.py`, `scripts/build_cases.py`와 같은 구성 (클래스마다 group 5개 × pair 4개,
  pair마다 변형 6개). pair의 N 뽑기 seed는 `f"42:{풀 이름}:{group id}:pairs"`다.
- 구축 뒤 점검 (하나라도 어기면 풀을 쓰지 않고 원인을 기록한다)
  - 기존 311장과의 중복 0, 풀 사이의 중복 0
  - 클래스마다 제외 뒤 P, N 후보가 8장 이상
  - 풀마다 pools, pairs, cases 파일의 SHA-256을 Stage 2 문서에 적는다
- 이 절차를 구현하는 코드는 풀을 만들기 전에 커밋하고, 그 커밋을 Stage 2 문서에 적는다.

## 3. 확증 가설 (확증 풀)

모델: Qwen2.5-VL-3B-Instruct, Qwen2.5-VL-7B-Instruct (bf16), 신규 VLM InternVL3.5-4B의 Transformers 형식
(`OpenGVLab/InternVL3_5-4B-HF`, bf16, revision SHA는 Stage 2에서 고정).

기울기 β(변형)는 같은 pair의 변형 margin을 PPP margin에 회귀한 클래스 내부 OLS 기울기다
(`mivlm.analysis.position_weights`, `experiments/01_baseline/persistence_slopes.py`, 커밋 e7cff4f).
전체 회귀의 기울기는 같은 구간으로 보조 보고만 한다.

| 가설 | 모델 | 통계량 | 구간 | 지지 | 반증 | 보류 | G3 |
|---|---|---|---|---|---|---|---|
| H1 | 3B | β(PPN) − β(PNP) | 98.3% | 상한 < 0 | 하한 > 0 | 그 밖 | 필수 |
| H2 | 7B | β(PPN) − β(PNP) | 98.3% | 상한 < 0 | 하한 > 0 | 그 밖 | 필수 |
| H3 | 7B | β(PPN) − β(NPP) | 98.3% | 상한 < 0 | 하한 > 0 | 그 밖 | 보조 |
| H4 | InternVL3.5-4B | N 1장 False-Yes 비율: 공동 질문(A) − 이미지별 질문의 AND(B) | 95% | 하한 > 0 | 상한 < 0 | 그 밖 | 필수 |

- 98.3%는 탐색 분석과 같은 자리 비교의 Bonferroni 수준(1 − 0.05/3)이다.
- H4의 비율은 확증 풀의 N 1장 케이스(PPN, PNP, NPP)를 모두 합친 값이다. 구간은 클래스마다 (A의 False-Yes 수,
  B의 False-Yes 수, 케이스 수)를 함께 다시 뽑아 합친 비율의 차이로 만든다.
- 방향: H1~H3은 "N이 마지막 자리에 있을 때 PPP margin이 1N margin에 덜 남는다"는 방향이다.
  H4는 "공동 질문이 이미지별 질문의 AND보다 False-Yes가 많다"는 방향이다.
- G3: H1, H2, H4가 모두 지지면 통과, 하나라도 반증이면 실패, 그 밖에는 보류.
- G3를 통과해도 반례에 특이한 메커니즘이나 모델 내부의 집계 방식이 입증된 것은 아니다.
  자리 비대칭은 일반적인 위치 가중치로도 설명될 수 있다 (4절의 보조 지표 참고).

## 4. 보조 보고와 탐색 분석 (판정 없음)

- 기울기 값 자체와 전체 회귀의 기울기, 자리 차이 세 쌍 전부
- 자리 가중치와 하락 몫: r_k = δ_k − δ̂_k, δ_k − ω_k, ρ_k, 가산 모형 대비 기울기 차이 (`experiments/02_decomposition/position_weights.py`).
  r_k의 동등성 범위 ±0.05는 탐색 기준으로만 쓰고 G3에 넣지 않는다
- NNP, NPN 변형 (7B의 NPN False-Yes, NNP Yes의 클래스 성향 의존), 이미지 수 k, 반전 질문: 케이스 구성은 Stage 2에서 정한다
- Fixed Logit Bias와 클래스별 손상 한도 기준선(8-A)의 확증 풀 값
- 위에 없는 분석은 모두 탐색으로 표시한다

## 5. 관문

| 관문 | 판정 시점 | 통과 조건 | 통과하지 못하면 |
|---|---|---|---|
| G1. Calibration 한계 | 8-A (탐색 데이터) | 5% 한도의 제약형 class_cv에서 평가 쪽 PPP 손상 ≤ 5%이고 합친 교정률 95% 구간 상한 < 50% | Calibration 중심 분석 |
| G2. Prompt 한계 | 15 (확증 풀) | 모델마다, 아래 순서로 판정 (표 아래 참고) | 프롬프트 해결책과 그 원인 분석 |
| G3. 현상 일반화 | 11-A~16 (확증 풀) | 3절의 규칙 | Qwen2.5-VL과 현재 조건에 한정한 분석 |
| G4. 개입 가능성 | 19 (개발 풀) | Full N 개입의 교정 효과가 같은 자리 P 대조와 Random 대조보다 큼. 두 대비의 구간 하한 > 0, PPP 손상을 함께 보고 | 인과 메커니즘 재검토 |
| G5. 선택적 교정 | 25 (봉인 평가 풀) | No-oracle, PPP 손상 ≤ 5%에서 같은 정보 조건의 실용 class bias보다 교정률이 높음. 차이 구간 하한 > 0 | 메커니즘 분석 논문 |

- G1의 현재 상태: 보류 (주 판정 3B bf16에서 평가 쪽 손상이 한도를 넘음). G1은 탐색 데이터의 기존 class_cv 결과를
  일부 본 뒤에 정한 탐색적 관문이다. 통과는 이 규칙(제약형 class_cv)의 한계를 뜻할 뿐, 모든 보정 방법의 한계가 아니다.
- G2: D의 PPP 손상률은 A에서 Yes로 맞힌 PPP 중 D가 No로 답한 비율이다. 모델마다 위에서부터 차례로 판정한다.
  1. PPP 손상률 > 5%: 보류 (손상 예산 위반). 아래 조건은 보지 않는다
  2. PPP 손상률 ≤ 5%이고 D의 N 1장 False-Yes 95% 구간 하한 ≥ 10%: 통과 (프롬프트만으로는 부족)
  3. PPP 손상률 ≤ 5%이고 같은 구간의 상한 < 10%: 실패 (프롬프트로 대부분 해결)
  4. 그 밖: 보류 (구간이 10%에 걸침)
  D의 프롬프트는 Stage 2에서 고정한다.
- G4, G5의 세부 정의(개입 위치, 대조군, 강도의 선택 범위)는 개입 연구를 시작하기 전에 등록한다.
- 공통 정의: PPP 손상률 = 원래 Yes로 맞힌 PPP 중 No로 바뀐 비율. False-Yes 교정률 = 원래 Yes로 틀린 N 1장 케이스 중
  No로 바뀐 비율.

## 7. 통계 방법

- 단위: 클래스. 같은 이미지를 여러 케이스가 쓰므로 케이스를 독립 표본으로 세지 않는다.
- 구간: 클래스를 복원 추출로 10,000번 다시 뽑은 백분위 구간. 뽑기의 seed는 0으로 고정한다 (`class_bootstrap_interval`).
- 여러 비교: 같은 묶음 안에서 Bonferroni로 구간 수준을 올린다 (자리 비교 98.3%).
- 값을 정할 수 없는 뽑기(nan)는 빼고 구간을 만들고, 그 수를 보고한다. 분모가 0에 가까운지는 상대 허용오차 1e-12로 본다.
- 판정은 지지, 반증, 보류 셋이다. 구간이 0을 포함하는 것을 "차이가 없다"로 읽지 않는다.
